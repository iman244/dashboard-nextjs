## Global Constraints

Every task inherits these. Copied verbatim from the charter.

1. **Persian is the priority; English is the second concern.** `en` is NOT dropped.
   Do not delete `messages/en.json`. UX-01 (English-only defects) is Wave 2 — out of
   scope for this plan.
2. **RTL is a first-class layout mode.** Prefer logical CSS properties
   (`ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`, `text-start`/`text-end`) over
   physical. Verify every visual change in `/fa`.
3. **No hardcoded user-facing strings.** All copy goes through the route-scoped
   namespaces in `messages/en.json` + `messages/fa.json`. Keep the two at key parity
   (229 keys at base). When adding a key, add it to **both** files.
4. **Do not touch** Persian-digit, Jalali-date, or number-formatting logic except
   where a task explicitly says to.
5. **No backend changes, no new features, no new routes, no dependency bumps.**
6. **Green bar before every commit:** `npm run build` then `npx tsc --noEmit` must
   both pass. `npm run lint` is red at baseline (33 errors / 48 warnings) — the bar
   is *do not increase those counts*, not reach zero.

### Task 4: Fix invisible chart fills and add legends

Fixes UX-03. Five series currently render with invalid CSS and paint nothing.

**Files:**
- Modify: `periodical-reports/_charts/record-count-chart.tsx:30`
- Modify: `periodical-reports/_charts/patient-count-chart.tsx:30`
- Modify: `patient-reports/_charts/service-count-chart.tsx:27`
- Modify: `saderat…/[id]/page.tsx:911, :1451, :250`

**Root cause** — verified: those call sites use `fill="hsl(var(--chart-N))"`, but
`globals.css:85-89` defines the tokens as `oklch()` values. `hsl(oklch(0.62 0.17 230))`
is invalid CSS and resolves to nothing. This is a Tailwind v3 → v4 migration artifact:
v3 shadcn stored bare HSL triplets that *required* the `hsl()` wrapper; v4 stores
complete `oklch()` colors that must be used bare. It fails silently — no console error,
no build warning.

- [ ] **Step 1: Confirm the failure set**

```bash
grep -rn "hsl(var(--chart" src/
```
Expected: exactly the 5 lines above. The correct pattern already in use is
`var(--chart-N)` at `[id]/page.tsx:449,497,541`.

- [ ] **Step 2: Replace the wrapper**

Change each `"hsl(var(--chart-N))"` to `"var(--chart-N)"`. Nothing else on those lines
changes.

- [ ] **Step 3: Replace the hardcoded pie palette**

`[id]/page.tsx:250` currently reads:

```tsx
const COLORS = ["black", "gray", "brown", "red", "orange"];
```

Black is invisible on the dark-mode background (`--background: oklch(0.129 …)`), and
red/brown/orange collapse into one hue under deuteranopia. Replace with the theme ramp:

```tsx
const COLORS = [
  "var(--chart-1)", "var(--chart-2)", "var(--chart-3)",
  "var(--chart-4)", "var(--chart-5)",
];
```

- [ ] **Step 4: Add legends**

No chart in the console renders a `<Legend>`. Add to the gender pie and to any chart
with more than one series, using the shadcn wrapper already available:


- [ ] **Step 6: Commit**
